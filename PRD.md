# Product Requirements Document — skills-mcp

**Summary:** Expose Claude skills in Codex via read-only MCP registry.

## Background
- Claude’s Skills feature lets models load task-specific instructions, scripts, and assets on demand (“progressive disclosure”), improving consistency and speed on specialized workflows.
- Codex lacks a native way to browse or inspect these Skills; users must manually open repositories like `anthropic-skills` and copy `SKILL.md` folders into projects.
- MCP servers are the preferred integration surface for Codex to discover external capabilities, making an MCP-based Skills registry the most direct path to bring Skills awareness into Codex sessions.
- The companion `anthropic-skills` repository provides canonical examples and structure for Skills; it will act as the seed catalog for this project.

## Goals
- Deliver an MCP server that surfaces a unified, read-only catalog of Skills to Codex by exposing each skill as an MCP resource with rich metadata and documentation snippets.
- Provide ergonomic discovery features (listing, filtering, search, diffing) so Codex users can quickly identify relevant Skills without leaving the CLI.
- Ship a thin Python CLI wrapper (sharing the same codebase) for offline browsing, validation, scaffolding of local skill copies, and importing Skills from remote repositories while respecting the server’s read-only contract.
- Ensure the solution can ingest multiple registries (e.g., bundled examples, user-defined directories) and cleanly separate upstream read-only skills from user workspaces.
- Document usage patterns so that future MCP-aware tooling (Codex prompts, Claude Code flows) can leverage the registry consistently.

## Non-Goals
- Executing or running scripts bundled inside Skills (explicitly out of scope; the server only reads metadata and files).
- Providing automated synchronization with remote Anthropic services or authenticated catalogs beyond local filesystem access.
- Re-implementing full skill editing within the MCP server; write operations live in the optional CLI wrapper or external tooling.
- Building a generic MCP server generator; scope is limited to Skills discovery and authoring support.

## Key Personas
- **Codex Developer:** Uses Codex CLI for day-to-day work, wants quick insight into available Skills to accelerate tasks without context switching.
- **Prompt Engineer / Workflow Designer:** Curates internal Skill libraries and needs confidence that Skill definitions remain discoverable and aligned with Claude’s expectations.
- **Team Maintainer:** Oversees the shared Skills repository, ensuring version drift between upstream examples and internal forks is detectable.

## User Stories & Scenarios
- As a Codex developer, I can browse all available Skills via MCP resources so I can decide which instruction bundle to reference in an active session.
- As a prompt engineer, I can query for Skills by tags, names, or descriptions to find workflows relevant to my current task.
- As a maintainer, I can inspect the YAML frontmatter and instruction outline for a Skill directly in Codex to verify compliance before adoption.
- As a maintainer, I can use the CLI wrapper to scaffold a new Skill from the template directory, ensuring required metadata fields are present.
- As a maintainer, I can compare the metadata hash or last-modified stamp of a local Skill against the upstream catalog to identify drift.

## Functional Requirements
1. **Registry Configuration:** Load Skills from the bundled `anthropic-skills` repo plus any user-defined directories registered via the CLI (persisted under the skills CLI configuration directory). Configuration should support prioritizing or grouping registries.
2. **Resource Exposure:** Publish each Skill as an MCP resource with metadata (name, description, source registry, tags if available) and a summarized instruction body. Provide pagination to prevent overloading responses.
3. **Skill Detail Retrieval:** Offer a read-only tool/resource call that returns the full `SKILL.md` content, split into frontmatter and body for downstream parsing.
4. **Search & Filtering:** Provide tools to filter Skills by name, description keywords, registry, or custom tags explicitly defined in frontmatter.
5. **Change Detection:** Surface lightweight change indicators (e.g., content hash, last modified timestamp) for each Skill so clients can spot updates between scans.
6. **Validation Utility (CLI):** Reuse core parsing logic in a CLI command that validates Skill structure (required fields, Markdown presence) and scaffolds new Skills from the template skill while placing them in a writable workspace.
7. **Remote Import:** Provide a CLI command to fetch a Skill (or set of Skills) from a remote Git repository or URL, snapshot it locally under the CLI configuration directory, and register it with the catalog.
8. **Metadata Export:** Allow exporting selected Skill metadata (e.g., to JSON/Markdown) through the CLI for documentation or review purposes.
9. **Documentation & Onboarding:** Provide README updates and inline help covering installation via `uv`, MCP registration steps, and example Codex prompts.

## Non-Functional Requirements
- **Language & Tooling:** Python 3.13, packaged and managed with `uv`.
- **MCP Compliance:** Follow MCP resource and tool semantics so Codex can auto-discover the registry without custom adapters.
- **Read-Only Guarantee:** MCP server must never mutate or execute Skill contents; all responses are deterministic reads from configured sources.
- **Offline Operation:** All core features work without network access once the repository is cloned; remote fetches are optional extensions.
- **Performance:** Listing operations should handle hundreds of Skills with sub-second response times on typical developer machines (target ≤ 500ms for cached directory scans).
- **Security:** Treat upstream registries as immutable; clearly demarcate user-writable directories to avoid accidental edits. No execution of bundled scripts.
- **Localization:** Metadata and outputs remain English-only for v1; parser accepts UTF-8 content but no additional translations ship.

## Success Metrics
- Time to discovery: Codex users can locate a relevant Skill within two MCP interactions or one CLI command.
- Catalog coverage: 100% of Skills in configured directories appear as MCP resources with valid metadata.
- Validation accuracy: CLI validator flags 100% of malformed `SKILL.md` frontmatter and passes compliant examples.
- Adoption indicator: At least one internal Codex workflow references the MCP registry within the pilot period.

## Dependencies & Inputs
- `anthropic-skills` repository for open-source Skill content and templates (seed catalog).
- MCP Python SDK or equivalent utilities for building the server.
- Codex CLI runtime capable of loading custom MCP servers.
- `uv` for dependency management and packaging.

## Risks & Mitigations
- **Risk:** Large Skill catalogs slow down listing.  
  **Mitigation:** Implement caching/indexing and incremental refresh with change detection.
- **Risk:** YAML schema drift across Skills.  
  **Mitigation:** Maintain schema validation rules in shared parser; surface warnings via CLI.
- **Risk:** Users expect write capabilities through MCP.  
  **Mitigation:** Document the read-only contract prominently and point to the CLI for authoring tasks.
- **Risk:** Future Anthropic updates to Skills format.  
  **Mitigation:** Encapsulate parsing logic and track upstream release notes; plan version negotiation.

## Decisions & Assumptions
- Tagging remains limited to explicit frontmatter fields; no derived tags from directory or file names.
- Initial catalog coverage comes exclusively from the open-source Skills in `anthropic-skills`. User-authored Skills and remote imports added through the CLI reside in the skills CLI configuration directory.
- English is the only supported language for metadata and documentation in v1.

## Acceptance Criteria
- Running the MCP server exposes resource listings and detail retrieval that mirror the underlying Skill files.
- The CLI wrapper can validate existing Skills, scaffold new template-based Skills into a user directory, and export metadata without requiring network access.
- Documentation covers installation, configuration, Codex integration steps, and example usage flows.
- Automated tests verify parsing, resource serialization, and CLI scaffolding behaviors against fixtures from `anthropic-skills`.
